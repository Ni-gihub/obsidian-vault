# 攻略記事の品質基準

## 1. 基本方針

攻略記事を読んだ人が、実際に攻略を進められることを重視する。

記事の目的に応じて、必要な条件、実行する手順、その結果どうなるのかを明確にする。すべての記事に同じ情報や説明を求めるのではなく、記事の種類に応じて必要な内容を定める。

## 2. 全記事に共通する基準

- 読者が記事の目的や内容を理解できること
- 記事の目的に必要な情報が明確に記載されていること
- 情報の正確性を重視すること
- 攻略手順を説明する記事では、実行した結果どうなるのかが分かること
- **目次は原則として設置する**

記事冒頭に「この記事で分かること」のような要約欄を設ける必要はない。見出しや本文から自然に内容へ入れる構成とし、同じ説明の重複を避ける。

## 3. 記事の種類ごとの基準

### 3.1 攻略手順の記事

読者が実際に同じ攻略を試せることを重視する。

記事の内容に応じて、以下の情報を記載する。

- 必要な解放条件
- 使用するキャラクター
- 必要な設定や準備
- 具体的な攻略手順
- 手順を実行した結果、どうなるのか
- 失敗しやすい点や注意事項

必要な項目は攻略方法によって異なるため、すべての記事に一律で要求するわけではない。

### 3.2 ボス攻略記事

ボスを実際に撃破できることを重視し、少なくとも次の情報を記事に含める。

- ボスの出現条件・場所
- **ボスのギミック・行動と攻略方針**
- **そのボスに関連するアンロック**
- **記事の最後に、実際にそのボスをクリアした構築**

「ボスのギミック・行動と攻略方針」では、ボスの行動や特徴、必要に応じた個別の対処方法に加えて、ボス全体をどう攻略するかという方針も説明する。特定のギミックへの対処に限らず、どのような構築や立ち回りが向いているかを紹介する。例えば、防御・回復を重視した耐久型にするか、火力を重視して短期決戦を狙うかなど、ボスに合わせた考え方を説明する。個別の対処方法や攻略方針を、それぞれ独立した必須見出しにする必要はない。

Vampire Survivorsのアンロックに関連する情報を掲載する場合は、該当する内容の**達成条件**と**達成報酬**を記載する。アンロック名を独立した項目として設ける必要はない。該当するアンロックがない場合は、この項目を省略してよい。

最後に掲載する構築は、単なるおすすめや理論上の候補ではなく、実際に撃破できた構成を示す。読者が攻略を再現する際の参考にできるようにする。記事内で説明する一般的な攻略方針と、最後に載せる実際のクリア構築は区別する。

画像や動画は、ギミックや立ち回りを文章だけで伝えにくい場合に補助として使用する。ボスのステータスなども、攻略に関係する場合に記載する。

### 3.3 ゲームの仕組み・知識を解説する記事

攻略の背景にある知識や、ゲームシステムの仕組みを理解できるようにする。

例えば、金策の基本的な考え方や、特定の方法で効率が上がる理由などを解説する。

これらの説明をすべての攻略記事に含めるのではなく、必要に応じて独立した解説記事として作成し、関連する攻略記事から参照できるようにする。

### 3.4 金策・効率などの検証記事

検証結果そのものに価値がある記事では、実際に検証したことが分かる情報を記載する。

- 検証に使用したゲームのバージョン
- 使用端末や実行環境
- 検証条件
- 検証方法
- 確認できた結果
- 実際に検証していることを示す画像

確認済みの結果と、推測や未検証の内容は区別する。

この基準は主に金策や効率検証などに適用し、すべての攻略記事に同じ形式の検証情報を要求しない。

## 4. 攻略方法が使えなくなった場合

ゲームの更新などによって攻略方法が成立しなくなった場合は、記事を公開し続けず、必要に応じて非公開にする。

公開日や最終確認日などの日付だけで、記事が古いかどうかを判断しない。攻略方法が現在も成立するかどうかを基準に判断する。

非公開にするための具体的な仕組みや管理画面については、現時点では決めない。

## 5. スマートフォン向けUI

スマートフォンから攻略情報を閲覧する読者を重視する。

具体的なUIは、実際にスマートフォンで使いやすいWebサイトを調査・参考にしながら設計する。画面構成、文字の読みやすさ、操作性、目次、表や画像の表示方法などは、品質基準とは分けて今後検討する。
