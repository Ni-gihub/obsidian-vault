# 攻略記事の品質基準

## 1. 基本方針

攻略記事を読んだ人が、実際に攻略を進められることを重視する。

記事の目的に応じて、必要な条件、実行する手順、その結果どうなるのかを明確にする。すべての記事に同じ情報や説明を求めるのではなく、記事の種類に応じて必要な内容を定める。

## 2. 全記事に共通する基準

- 読者が記事の目的や内容を理解できること
- 記事の目的に必要な情報が明確に記載されていること
- 情報の正確性を重視すること
- 攻略手順を説明する記事では、実行した結果どうなるのかが分かること
- **目次は原則として設置する**

記事冒頭に「この記事で分かること」のような要約欄を設ける必要はない。見出しや本文から自然に内容へ入れる構成とし、同じ説明の重複を避ける。

### バージョン・更新日の記載基準

- 記事に記載するゲームバージョンは、**iPhone版のApp Storeで公開されているバージョンを基準**とする。
- 記事に表示する「更新日」は、ゲームやDLCの配信日ではなく、**その記事を実際に更新した日**とする。

## 3. 記事の種類ごとの基準

### 3.1 攻略手順の記事

読者が実際に同じ攻略を試せることを重視する。

記事の内容に応じて、以下の情報を記載する。

- 必要な解放条件
- 使用するキャラクター
- 必要な設定や準備
- 具体的な攻略手順
- 手順を実行した結果、どうなるのか
- 失敗しやすい点や注意事項

必要な項目は攻略方法によって異なるため、すべての記事に一律で要求するわけではない。

### 3.2 ボス攻略記事

ボスを実際に撃破できることを重視し、少なくとも次の情報を記事に含める。

- ボスの出現条件・場所
- **ボスのギミック・行動**
- **攻略方針・実際にクリアした構築**
- **関連するアンロック（記事の最後に配置）**

#### ボスのギミック・行動

ボスの行動や特徴を解説し、必要に応じて個別のギミックへの対処方法や撃破のポイントもあわせて説明する。対処方法を独立した必須見出しにする必要はない。

#### 攻略方針・実際にクリアした構築

まず、特定のギミックへの対処だけでなく、ボス全体をどう攻略するかという方針を説明する。どのような構築や立ち回りが向いているかを紹介する。例えば、防御・回復を重視した耐久型にするか、火力を重視して短期決戦を狙うかなど、ボスに合わせた考え方を説明する。

そのうえで、実際にそのボスを撃破できた構築を掲載する。単なるおすすめや理論上の候補ではなく、実際にクリアした構成を示し、読者が攻略を再現する際の参考にできるようにする。攻略方針で説明する構築の方向性と、実際に使用したクリア構築を同じ項目内でつなげて説明する。

#### 関連するアンロック

記事の最後に配置する。Vampire Survivorsのアンロックに関連する情報として、該当する内容の**達成条件**と**達成報酬**を記載する。アンロック名を独立した項目として設ける必要はない。該当するアンロックがない場合は、この項目を省略してよい。

画像や動画は、ギミックや立ち回りを文章だけで伝えにくい場合に補助として使用する。ボスのステータスなども、攻略に関係する場合に記載する。

### 3.3 ステージ攻略記事

ステージごとのクリア条件を達成できることを重視する。記事の基本構成は以下を目安とする。

- **ステージのギミック・敵の出現情報**
- **攻略方針・実際にクリアした構築**
- **関連するアンロック（記事の最後に配置）**

クリア条件や生存時間は独立した大見出しにせず、記事冒頭などに小さく記載するか、攻略方針の説明の中で自然に触れる。ステージによって条件が異なるため、30分生存など特定の条件に限定しない。

#### ステージのギミック・敵の出現情報

ステージ固有のギミック、イベント、特殊な仕組みなど、攻略に関係する情報を説明する。必要に応じて、時間ごとに出現する敵や注意すべき出現タイミングを表などで整理する。すべての敵や出現情報を網羅することを必須とはせず、攻略に役立つ情報を選んで掲載する。

#### 攻略方針・実際にクリアした構築

ステージ全体をどう攻略するかという方針を説明したうえで、実際にそのステージのクリア条件を達成できた構築を掲載する。攻略方針と実際に使用したクリア構築を同じ項目内でつなげて説明し、読者が攻略を再現する際の参考にできるようにする。

#### 関連するアンロック

記事の最後に配置する。関連するアンロックがある場合は、該当する内容の**達成条件**と**達成報酬**を記載する。アンロック名を独立した項目として設ける必要はない。該当するアンロックがない場合は、この項目を省略してよい。

画像や動画は、ギミックや敵の出現、立ち回りを文章だけで伝えにくい場合に補助として使用する。

### 3.4 キャラクター一覧・詳細ページ

キャラクター情報は、**本編・DLCごとの一覧ページ**と、**キャラクターごとの詳細ページ**で構成する。

#### キャラクター一覧ページ

- 本編と各DLCに分けて掲載する。
- 各グループ内はゲーム内と同じ順番にする。
- 一覧に表示する情報は、基本的にキャラクターアイコンとキャラクター名のみとし、アイコンを上、名前をその下に配置する。
- キャラクターアイコンと名前をひとまとまりのリンクとして、それぞれのキャラクター詳細ページへ移動できるようにする。

#### キャラクター詳細ページ

各キャラクターの詳細ページでは、次の3つを基本として掲載する。

- **画像**：キャラクターの見た目が分かる画像
- **入手方法**：解放条件や入手手順
- **性能**：ゲーム内の説明をそのまま掲載するだけではなく、固有能力やステータスなどの効果・仕様を詳しく解説する

性能の詳しい説明は、既存のnote記事を参考にする。

- [レガシー・オブ・ザ・ブラッドムーン キャラクター解説](https://note.com/neo_magical/n/n9682c7eeb0c9)
- [アンティの間 キャラクター解説](https://note.com/neo_magical/n/ndc25347a5015)

説明では、ゲーム内の表記だけでは分かりにくい挙動や効果を具体的に解説する。キャラクターの性能に応じて、次のような情報を必要な範囲で取り上げる。

- 能力・パッシブ・初期武器などの効果
- 能力が発動する条件やタイミング
- 発動したときに起こる具体的な変化
- ダメージ倍率、確率、持続時間、増加量などの数値
- レベル、HP、撃破数、呪いなど、条件による効果の変化
- 発動回数・所持数などの上限、例外、無効化される条件

上記を全キャラクターに一律で当てはめる必要はない。そのキャラクターに存在する固有仕様を選び、読者が実際の挙動を理解できるように説明する。おすすめ武器・相性のよいアルカナ・運用評価なども、説明に必要な場合だけ性能の中で扱う。

### 3.5 ゲームの仕組み・知識を解説する記事

攻略の背景にある知識や、ゲームシステムの仕組みを理解できるようにする。

例えば、金策の基本的な考え方や、特定の方法で効率が上がる理由などを解説する。

これらの説明は必要に応じて独立した解説記事として作成する。それぞれの記事は、その記事を訪れた読者の目的を単体で満たせる内容にする。記事末尾に関連記事をまとめて別の記事への移動を促す構成にはしない。

### 3.6 金策・効率などの検証記事

検証結果そのものに価値がある記事では、実際に検証したことが分かる情報を記載する。

- 検証に使用したゲームのバージョン（iPhone版App Storeのバージョンを基準とする）
- 使用端末の機種名・仕様、および必要な実行環境
- 検証条件
- 検証方法
- 確認できた結果
- 実際に検証していることを示す画像

確認済みの結果と、推測や未検証の内容は区別する。

この基準は主に金策や効率検証などに適用し、すべての攻略記事に同じ形式の検証情報を要求しない。

### 3.7 金策の仕組み・基本解説記事

金策全体に関する知識をまとめ、個別の金策構築を理解するための基礎情報を提供する。基本構成は以下を目安とする。

1. **目次**
2. **金策の種類**：ゴールドフィーバー、金貨袋、悪食の瞳など、金策に関係する方法や仕組みを紹介する。
3. **ゴールドフィーバーの仕組み**：発動条件、持続時間、延長、減衰など、金策の中心となる仕組みを解説する。
4. **金策向けキャラクター**：ビッグ・トラウザー、サミーなど、金策に向いているキャラクターと、その理由を説明する。
5. **金策向け武器**：金策に使える武器と効果、採用する理由を説明する。
6. **金策向けアルカナ**：金策に関係するアルカナの効果と、採用する理由を説明する。
7. **金策に関係する設定**：ステージ設定、ゲーム速度、エフェクトなど、金策効率に関係する設定を説明する。
8. **効率の検証・比較**：実際のプレイ結果をもとに、方法や条件による効率を比較する。

キャラクター・武器・アルカナ・設定は、単に効果や性能を列挙するのではなく、金策にどう役立つのか、なぜ効率に影響するのかを説明する。個別の金策構築の具体的な手順や構成は、金策構築記事で扱う。基本解説と金策構築は役割を分けつつ、それぞれ単体で読者の目的を満たす内容にする。関連記事やサイト内の案内を掲載する場合は、記事末尾にまとめず、ページ横のサイドバーに配置する。サイドバーの具体的な掲載内容や表示方法はサイト全体のレイアウト設計で決める。

検証・比較では、実測した条件と結果が分かるようにし、確認できた内容と推測を区別する。

### 3.8 金策構築記事

金策に使用する構築を紹介し、読者が同じ方法を実践できることを重視する。基本構成は以下を目安とする。

- **キャラクターの性能・評価**：金策との相性、特徴、強み・弱み
- **使用ステージ・設定**：ステージ、ゲーム設定、必要な条件
- **金策構築・実践方法**：使用する武器・パッシブ・アルカナなどの構築、取得順、立ち回り、実際の稼ぎ方、検証結果

構築・実践方法の項目内で、黄金の卵の段階など条件別の構築をまとめて紹介してよい。構築、取得順、操作方法、稼ぎ方、検証結果を細かく独立した必須見出しに分けず、一連の実践方法として説明する。

実際に稼げたゴールド量や所要時間などの検証結果は、構築・実践方法と関連付けて示す。検証条件や結果が複数ある場合は、比較しやすい表や画像などを使って整理する。実測値と推測値は区別する。

### 3.9 アップデート情報ページ

バージョンごとにページを作成し、noteに掲載したアップデート情報を原則そのまま掲載する。

- アップデート情報の文章・内容は、noteに掲載したものをそのまま使用する。サイト向けに要約・再構成せず、noteと同じ情報を読めるようにする。
- 無料アップデートとDLCの内容は分けず、同じバージョンのページ内で扱う。
- 既存の攻略方法に影響する変更は、どのような影響があるかをバージョンページ内で説明する。
- 記事末尾に関連記事・おすすめ記事をまとめる枠は設けない。関連記事やサイト内の案内を配置する場合は、ページ横のサイドバーで扱う。記事末尾にまとめる方式は採用しない。
- バージョン番号を明記し、どの更新についての情報か分かるようにする。
- noteで先行発信した情報を掲載する場合は、必要に応じて元のnote記事にもリンクする。

## 4. 攻略方法が使えなくなった場合

ゲームの更新などによって攻略方法が成立しなくなった場合は、記事を公開し続けず、必要に応じて非公開にする。

公開日や最終確認日などの日付だけで、記事が古いかどうかを判断しない。攻略方法が現在も成立するかどうかを基準に判断する。

非公開にするための具体的な仕組みや管理画面については、現時点では決めない。

## 5. スマートフォン向けUI

スマートフォンから攻略情報を閲覧する読者を重視する。

具体的なUIは、実際にスマートフォンで使いやすい複数のWebサイトを調査・比較しながら設計する。画面構成、文字の読みやすさ、操作性、目次、表や画像の表示方法などを、実際のコンテンツに当てはめて試行錯誤する。スマートフォンでの一覧・記事の見やすさと使いやすさは、特に時間をかけて検討する。


## 4. 一覧ページの表示・並び順

一覧ページは、読者が目的のコンテンツを画像と名称から見つけられることを重視する。基本情報は画像と名称のみとし、詳しい説明は移動先の記事・ページ内に掲載する。本編とDLCの区切りは、基本的に見出しや区切り線で表現する。検索・ソート・フィルターを設けず、あらかじめ決めた分類と並び順で探せるようにする。カード形式など具体的なレイアウトは、参考サイトを調査してから決める。

### 4.1 ステージ攻略一覧

- 本編を最初に掲載し、その後にDLCを掲載する。
- DLCは新しいものから順番にする。
- 画像とステージ名を組み合わせて表示する。具体的なレイアウト形式は未決定とする。

### 4.2 ボス攻略一覧

- 本編とDLCに分けて掲載する。
- 基本的に、ボスが出現するステージの順番で並べる。
- 画像とボス名を組み合わせて表示する。

### 4.3 キャラクター情報一覧

- 本編とDLCに分けて掲載する。
- 各グループ内はゲーム内と同じ順番にする。
- キャラクターアイコンを上、キャラクター名をその下に表示し、選択するとキャラクターごとの詳細ページへ移動できるようにする。

### 4.4 アンロック攻略一覧

- 本編とDLCに分けて掲載する。
- 各グループ内はゲーム内と同じ順番にする。
- 画像とアンロック名を基本とする。

### 4.5 金策構築一覧

- 現状は2体のキャラクターによる構築を基本とする。
- 新しい金策構築が増えた場合は、同じ一覧に追加する。
- 現時点では、構築数が少ないことを前提にした複雑な分類や検索機能を設けない。
